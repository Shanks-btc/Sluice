# Mainnet dry run: a FORK SIMULATION

**This is a simulation on a local fork of QIE mainnet, not a run on mainnet.** Nothing in it was sent to mainnet or to any network. It says nothing about how the real chain, the real explorer, the real public RPC endpoints or a real wallet behave. It shows that the scripts, their flags, their guards and the settings files work together, in the order the founder will run them.

Generated by `pnpm mainnet:dryrun` on 2026-11-26T13:07:01Z. The fork was made from QIE mainnet's state at block 12186637 (read-only calls to the public RPC), and lives in memory only. Regenerate this file by running the command again; it is overwritten, not edited by hand. Two lines about the refund are an exception: they were edited by hand on 2026-11-26, and each says so.

## What is real and what is not

| Real | Not real |
| --- | --- |
| The scripts and their flags, exactly as the runbook names them | The chain: a copy held in memory, whose blocks are made on demand |
| The real QUSDC contract, with its code and state as the fork read them | Every key: the keys were made for this run and thrown away. Every balance given to them: QUSDC and QIE were created on the fork only |
| The compiled router and vault | The explorer: there is none, so source verification and `verify-link` are not run (the dry run's pre-flight check reads a local stand-in) |
| The facilitator and the tool server as separate processes, started from the settings files `live:wire` wrote | The clock: the fork's was moved up to the wall clock |
| The payment proxy, the recorder and the checks, reading the chain through read-only methods | The router's owner and fee recipient: addresses with no key stand in for the founder's |
| The settings and the caps of the deploy, the smoke run and the payer's start, read out of the go-live plan's own commands | The founder's keys: no real key signs anything here |

One setting differs from the founder's: `SLUICE_RPC_URL`, which names the fork. On mainnet it is left unset, and the scripts probe QIE's five public endpoints.

## What building and running this found

These were faults in the scripts or the runbook that this run, or the runs before it, exposed. Each was fixed before this log was written, and is in DECISIONS.md.

- A recorder that had written its row then died with a Node 24 assertion on Windows (exit code 3221226505), because the program called `process.exit()` while a connection was closing. Commands now set their exit code and let the process end by itself.
- The runbook's last step said the builder withdraws and gave no command. `pnpm client:owner` now has `withdraw` and `refund`, by signature, for a builder or a payer with no QIE.
- `deploy.ts` and `smoke.ts` ignored an option they did not know, so a mistyped `--dry-run` would have run for real. They refuse it now.
- A facilitator, a tool server or a wallet MCP pointed at a node on another chain by a named RPC address would have started. They check the chain now.
- A tool call that needs a contract the fork has not yet read failed with the tool server's ten-second limit on one RPC read. On mainnet a read takes about a second. The limit was raised for this run only.
- The go-live plan's own settings did not all pass the guard they were written for. A cap on one transaction left over from the smoke run was above the cap on the payer's own QIE, so the payer's start would have been refused with `SLUICE_MAX_TX_QIE is above SLUICE_MAX_QIE`. The plan's tests now run each sending step's settings through the real guard, and the payer's step sets its own cap. This run reads the same settings out of the plan's lines.
- The plan's tests, run from the repository folder, could have read the founder's real key files, which the plan command looks for in the folder it is run from. They now run in an empty folder.
- Once the deployment and the smoke run had been made on mainnet, the real deployer held 0.0015 QUSDC less than a smoke run from the start deposits, and this run, which gave its own deployer exactly that, was stopped by the pre-flight check with `NO-GO`, as it should be. The run now takes the real holdings only when they are enough for a run from the start, and says which amounts it used.
- `pnpm live:verify` submits the router only. The vault, which the router's constructor creates, has its code compared with the compiled AgentVault instead (`pnpm live:vaultcheck`). What QIE's explorer answered about the vault is in EXPLORER-VAULT-INVESTIGATION.md.

## What this does not show

- How mainnet, its explorer or its public endpoints behave: the explorer's source verification (`pnpm live:verify`), its 502s and the rate limits of rpc1 to rpc5 were not exercised.
- A real wallet, a real multisig, a real host, real latency, or whether a transaction as large as the biggest batch is accepted by the live chain.
- Any recorded row as evidence: the rows were written to a copy of the evidence file under a Fork heading, are never read by the proof strip or counted by `pnpm evidence:summary`, and are not on mainnet.
- Anything about QUSDC's behaviour on the live chain beyond what the fork copied, and nothing about how the live chain's state will differ when the founder runs this.
